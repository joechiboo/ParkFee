# 管理密碼外洩處理

> 給誰看：系統管理者（使用者本人）與陳經理。
> 什麼時候看：懷疑管理密碼被不該知道的人拿到，或發現名冊、車位被不明人士改動。
> 2026-11-10 整理。本檔不寫密碼本身（repo 公開）。

## 一、先做這三步

| 步驟 | 誰做 | 做什麼 |
|---|---|---|
| 1. 換密碼 | 系統管理者 | 換掉後舊密碼立刻失效（見第二節） |
| 2. 查動過什麼 | 系統管理者 | 從稽核紀錄列出外洩期間的所有管理動作（見第三節） |
| 3. 改回來、發新密碼 | 經理＋秘書 | 拿最近一份名冊備份比對，把被改的改回去；新密碼只交給需要的人 |

經理或秘書發現異狀時，先通知系統管理者換密碼，其他事等換完再做。換密碼只有系統管理者能做。

## 二、換密碼

在 ParkFee 專案根目錄的 PowerShell 執行（把「新密碼」換成實際要用的字串）：

```
npx.cmd --yes supabase secrets set ADMIN_PASSWORD=新密碼
```

- 密碼只存在後端，網頁程式裡沒有，所以**不用重新發布網站**，約一分鐘內生效。
- 出現 `AccessTokenRequiredError` 時先跑 `npx.cmd --yes supabase login`，在瀏覽器按授權後重跑。
- 換完用舊密碼登入 `admin`、開「📋 名冊」，應顯示「管理員驗證失敗」；用新密碼應看得到名冊。
- 系統管理者用自己的戶號加自己登記的車牌登入，管理權不靠這組密碼，換密碼期間不受影響。
- 新密碼不要寫進 repo、LINE 群組或講義，個別交給經理與秘書。

## 三、查對方做了什麼

稽核紀錄存在資料庫的 `audit_log` 表，目前沒有查看畫面，要下指令查。下面這行列出最近 7 天所有管理動作（唯讀，不會改資料）：

```
npx --yes supabase db query --remote --read-only "select to_char(at at time zone 'Asia/Taipei','MM-DD HH24:MI') 時間, action 動作, actor 身分, target 對象, ok 成功, detail 摘要 from audit_log where at > now() - interval '7 days' order by at"
```

| 動作代碼 | 意思 |
|---|---|
| `roster.list` | 撈全名冊（含電話、車號）。外洩時先看這個，判斷個資有沒有被拿走 |
| `household.rename` | 更正戶號 |
| `household.update` | 管理員代改某戶的登記 |
| `seat.assign`、`seat.unlock`、`seat.release` | 指派、解除、放棄車位 |
| `pay.batch` | 批次標記繳費 |
| `result.publish` | 發佈抽籤結果 |

**稽核紀錄的限制**

- 用管理密碼做的動作，身分一律記成 `password`，分不出是經理、秘書還是外人，只能用時間判斷。
- 只記「對哪一戶、哪一格做了什麼」，不記改之前的內容。要知道原本的值，得靠名冊備份。
- 住戶自己改登記不記；直接對資料庫下指令的維護（例如清測試資料）也不記，那類記在 `TODO.md`。

## 四、拿到密碼的人能做什麼

| 能做 | 做不到 |
|---|---|
| 看全名冊（電話、車號） | 刪除整戶登記（系統沒有這個功能） |
| 代改任一戶的登記、更正戶號 | 拿到資料庫本身的金鑰 |
| 指派或解除車位、標記已繳費 | 改網站程式 |
| 發佈抽籤結果 | 動社區幫的帳單與金流（那是另一套系統、另一組帳號） |
| 登記時窗關閉時補登新戶 | |

名冊若確定被撈走，屬個資外洩，要由管委會決定是否通知住戶。

## 五、平常就要做：留名冊備份

資料庫是免費方案，沒有自動備份可還原。被改動後要知道原本的值，只能靠自己留的備份。

### 5.1 快照到本機 SQL Server Express（主要做法，2026-11-10）

```
node scripts/backup-to-sqlexpress.mjs
```

- 對正式站只讀。把全部登記（戶、車輛、鎖定車位）抄成一份新快照，寫進本機 `localhost\SQLEXPRESS` 的 `ParkFeeBackup` 資料庫；每跑一次多一份，不覆蓋舊的。稽核紀錄也一併抄下來（只補新的）。
- 跑完會印這次與上一份快照的差異：戶與車各新增、消失、內容變動幾筆。
- 需要先 `npx supabase login`。資料含電話與車號，只存在系統管理者的電腦。
- **每天自動跑（2026-11-13 已建）**：Windows 工作排程器的「ParkFee 名冊每日備份」，每天 12:30 執行，當下沒開機會在下次開機登入後補跑，到 2027/01/15 自動停止。執行紀錄在 `private/backup-log.txt`。建好當天手動觸發過一次，成功寫入快照。
  - 只在系統管理者登入 Windows 時才會跑（用的是他的 Supabase 登入身分）。電腦關機或登出的那幾天沒有快照。
  - 重建或改時間：

```powershell
$action = New-ScheduledTaskAction -Execute 'cmd.exe' -Argument '/c "cd /d D:\Personal\Project\ParkFee && node scriptsackup-to-sqlexpress.mjs >> privateackup-log.txt 2>&1"'
$trigger = New-ScheduledTaskTrigger -Daily -At '12:30'
$trigger.EndBoundary = '2027-01-15T23:59:00'
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Minutes 10)
Register-ScheduledTask -TaskName 'ParkFee 名冊每日備份' -Action $action -Trigger $trigger -Settings $settings -Force
```

  不要了就跑 `Unregister-ScheduledTask -TaskName 'ParkFee 名冊每日備份' -Confirm:$false`。

**定期檢視備份成果**

```
node scripts/backup-review.mjs          # 快照清單、每天有沒有備份、最早一份到最新一份之間變了什麼
node scripts/backup-review.mjs 6 12     # 指定比對快照 #6 與 #12
```

只讀本機資料庫。會列出這段期間新登記的戶、消失的戶、電話或志願有變的戶、車輛有變的戶、已選定車位數與鎖定格數的變化、期間的管理動作。「消失的戶」正常應該是 0（系統沒有刪戶功能；更正戶號會同時出現一戶消失、一戶新增）。

**怎麼查**（用 SSMS 或 `sqlcmd -S "localhost\SQLEXPRESS" -E -C -d ParkFeeBackup`）

```sql
-- 有哪些快照
select * from snapshot order by id desc;

-- 某一戶歷次快照的內容（看什麼時候被改、原本是什麼）
select s.taken_at, h.* from household_snap h join snapshot s on s.id = h.snapshot_id where h.戶號 = N'H3-6' order by s.id;
select s.taken_at, v.* from vehicle_snap v join snapshot s on s.id = v.snapshot_id where v.戶號 = N'H3-6' order by s.id, v.第幾輛;

-- 兩份快照之間哪些車的內容不一樣（把 5、6 換成要比的快照編號）
select 車號, 戶號, 車種, 車位編號, 配位狀態, 已繳費 from vehicle_snap where snapshot_id = 6
except
select 車號, 戶號, 車種, 車位編號, 配位狀態, 已繳費 from vehicle_snap where snapshot_id = 5;
```

快照只是備份，沒有自動還原。要改回去時，查出原本的值後到「📋 名冊」頁人工改。

### 5.2 名冊頁匯出（備援）

管理員登入後到「📋 名冊」按「匯出 Excel（CSV）」，存到不公開的地方。系統管理者的電腦不在手邊、或要把名冊交給經理時用這個。

抽籤的配位結果 CSV 本來就要留（見 [14](14-抽籤作業手冊.md)、[37](37-社區幫出帳與繳費回查作業.md)），那也是備份的一部分。

## 六、降低外洩機會

- 密碼只給實際要操作的人，人員異動時換密碼。
- 不在公用電腦勾「記住密碼」；用完按右上角登出。
- 這組密碼是共用的，無法做到每人一組。要能追到個人，得改成每位管理員各自的帳號，目前未做。
