# ParkFee — 配位作業流程設計（Phase I）

> 本文記錄「抽籤 → 選位 → 結果」的端到端流程設計與待決事項。
> 規則唯一事實來源：`docs/管理辦法.pdf`。本文如與辦法衝突，以辦法為準。
> 最後更新：2026-06-06。

## 階段切分

- **Phase I（進行中）**：配位核心 — 抽籤 → 選位 → 結果。
- **Phase II（延後）**：住戶線上登記表單（含車牌 OCR）、繳費系統、eTag 白名單匯出、巡邏稽核。

## 端到端流程（依辦法時程）

```
①登記期(11/15–11/30)
   住戶線上登記 → 名冊(戶號·車號·車種·第幾輛·身障·志願小位)
   辦法：一戶僅得先登記一個機車位；未登記者以棄權論               ✓ 規則已定
        │
        ▼
②抽籤＝電腦隨機抽選「順序號」（可重現：公告種子 / 執行時間 / 監察委員）
   Round 0 無障礙(身障優先, ≤8全配 / >8抽8未中併入R1)
   Round 1 一戶一位(志願小位免抽選小位 / 其餘抽資格＋順序號)
   Round 2+ 第二位起(辦法：如有剩餘再抽；需求≤剩餘全配, 超額抽+候補)  ✓ 引擎已做
        │
        ▼
③人工選位：中籤者依順序號逐一選剩餘車位（選課式，非自動指派）      ✅ 已定（決策 A）
        │
        ▼
④公告配位結果                                                  ✓ 結果頁待做
        │
        ▼
⑤簽約繳費（公告日+5日內；一般 1,200/年、重機 3,600/年）
   辦法：公告後 10 日內未辦妥視同放棄                            ❓ 是否進 Phase I（決策 B）
        │
        ▼
⑥放棄 → 候補遞補；空出車位回到池                                ❓ 流程/時機未定（決策 B）
        │
        ▼
⑦如有剩餘 → 回到 ②跑下一輪                                     ❓ 三輪時程未定（決策 C）
```

## 待拍板決策（管委會 / 權責委員）

| # | 決策點 | 選項 | 目前預設 |
|---|---|---|---|
| ~~A~~ | 選位模式 | ✅ **已定（2026-06-06）：真人互動「人工選位」** — 電腦抽順序號，中籤者依序號逐一選位，非自動配 | 需做選位 UI（平面圖點選 + 順序輪流）；引擎的自動配結果改為「順序」輸出 |
| **B** | 繳費 / 放棄 / 候補遞補是否進 Phase I | 進（完整閉環）/ 歸 Phase II（先只到公告結果） | 傾向 Phase II，但「遞補」會回頭影響結果 |
| **C** | 三輪時程 | 同日連跑（算完即定）/ 分次（每輪公告→繳費→遞補後才開下一輪） | 辦法「如有剩餘再抽」偏分次，但未寫間隔 |
| **D** | 重機不足額時 | 列候補 / 給單一大位暫用 / 不予登記 | 目前：列「未配」並註明原因（程式碼已標 TODO） |
| **E** | Phase I 資料源 | 最簡 CSV 匯入 / 一鍵範例名冊 / 兩者 | 兩者都做 |

## 兩條可走路線

> 註：決策 A 已定為**人工互動選位**，故「選位自動配」不再是選項；以下兩條路線差異改在「三輪時程 + 繳費遞補」（決策 B/C）。

- **簡單版 MVP**：三輪同日連跑 + 繳費/遞補歸 Phase II
  → 抽籤引擎跑出順序號 → 選位 UI 依序人工選位 → 結果頁。
- **貼真實作業**：分次公告 + 繳費遞補
  → 引擎需加「輪次狀態機 + 候補遞補」，UI 頁面更多，工時較長。
