# 社區幫費用匯入 — 格式與產製規劃

> 目的：12/1 配位完成後，把**機車位維護清潔費**做成社區幫匯入檔收款。
> 格式依據：使用者提供之實際檔「第三屆管理費115年05月管理費.csv」（真實帳務資料，**已 gitignore 不進版控**，放 `private/`）。
> 2026-08-24 建立。

## 1. 檔案格式（由範本檔逆推）

- **編碼：Big5、無 BOM**（非 UTF-8；匯出時須轉碼）。
- 範本檔 657 列含表頭 → **656 資料列，但只有 655 戶**。
  ⚠️ **不是一戶一列**：`#F1-321` 2 樓被拆成兩列（一列管理費 1654、一列汽車清潔費 500），
  物業把兩筆帳分開立。**列數 ≠ 戶數**，寫程式時別把 656 當戶數。
  戶數組成：住宅 A–H 640 戶（A 85、B 71、C 72、D 84、E 98、F 66、G 66、H 98）＋店面 S1–S15 15 戶＝**655**。
  （與車位編號到 655 純屬巧合，兩者無關，勿在文件中混用此數字。）
- 欄位：

| 欄 | 內容 | 範例 |
|---|---|---|
| 住戶住址(門牌號) | `#棟-街號` | `#A1-375` |
| 住戶住址(樓層) | 數字 | `3` |
| 住戶住址(之) | 數字，無則 0 | `0` |
| 收費類別 | `YYYY年MM月管理費`（西元） | `2026年05月管理費` |
| 備註 | 空 | |
| 細項(列舉參考欄位) | 固定字串 | `#管理費#汽車清潔費#機車清潔費#附加費用` |
| 立帳通知日期 | `YYYY/M/D` | `2026/4/25` |
| 繳費期限 | `YYYY/M/D` | `2026/5/25` |
| 管理費 | 坪數 × 90 | `1757` |
| 汽車清潔費 | 汽車位數 × 500 | `500` |
| 機車清潔費 | 目前全 0 ← **我們要填的欄** | `0` |
| 附加費用 | 0 | `0` |

- 立帳約前月 25 日、繳費期限約當月 25 日。
- 2026 年 11 月（含）以後，交屋預繳管理費均已滿期，**無破月問題**，各戶金額規則化。

## 3. 產製方式

**script：`scripts/build-shequbang-import.mjs`** ✅ 2026-09-09 已建（測試 `build-shequbang-import.test.mjs`，22 項）

輸入固定兩份：

1. 物業提供的**管理費檔**（用來查門牌；門牌不隨月份變動，**用哪個月的都行**）
2. **配位結果 CSV**（`src/export/result.js` 產出：戶號、車號、車位編號、車位類型、應繳金額、簽約期限、狀態、備註）

> **不需要另外維護「戶號↔門牌對照表」。** 物業檔本身就含全部 655 戶門牌，
> 腳本執行時即時換算，沒有第二份檔案要同步、也不會過期。
> 街號無法從戶號反推（見下），所以物業檔是必要輸入，但只當「查門牌用的對照來源」。

### 兩種輸出模式

**`--mode standalone`（預設，建議）— 獨立出一張「機車位費用」帳單**

- 收費類別另立為「**116 年度機車位清潔費**」（`--category` 可改），帳單上看得懂這筆是什麼錢
  - 預設用**民國年**：與登記表「116 年度」、物業檔名「…115年05月管理費」一致，住戶對得起來
  - ✅ **2026-09-17 實測：社區幫接受此收費類別**（原擔心它只吃「YYYY年MM月管理費」格式，確認無此限制）
  - 要改西元用 `--category "2027年度機車位清潔費"`
- **管理費／汽車清潔費／附加費用一律 0**，只有機車清潔費有值
- **只列有金額的戶**（模擬為 244 列）——全 655 戶都出一列會產生 400 多張 0 元帳單；純自行車戶 0 元亦不出帳
- **立帳通知日期＝匯出當日**（`--bill-date` 可改）—— 社區幫的「立帳」是帳單建立那天，
  與抽籤公告日無關；公告後可能隔幾天才產檔上傳，用公告日會讓立帳日早於實際建帳日（2026-09-17 實測修正）
- **繳費期限＝公告日 + 10 日**（`--due-days` 可改），見下方時程表
- 依門牌、樓層排序，方便物業肉眼核對
- 好處：不受物業月結檔出檔時程綁住、**沒有多列戶問題**、帳單品名清楚

#### ⚠️ 公告日決定一切 —— 建議訂 12/5

繳費期限錨定公告日，所以公告日訂哪天就決定收款截止。若 12/2 公告，放棄線落在 12/12；
想收到 12/15，**把正式公告日訂 12/5 即可，辦法一個字都不用改**：

| 階段 | 日期 | 依據 |
|---|---|---|
| 抽籤 | 12/1 | 伍二（九） |
| 驗證、製表 | 12/2–12/4 | 作業 |
| **正式公告** | **12/5** | 起算點 |
| 簽約繳費期限 | 12/10 | 公告 + 5 日〔伍二（六）〕 |
| **放棄線＝帳單到期日** | **12/15** | 公告 + 10 日〔伍二（六）〕 |
| 使用期間起 | 次年 1/1 | 曆年制 |

對應指令：`--announce 2026-12-05`（預設 `--due-days 10` 即得 12/15）。

⚠️ **不能再往後拉**：社區幫慣例的「當月 25 日到期」明顯超過辦法伍二（六）的 10 日放棄線，
帳單還沒到期資格就先失效，判定會打架。要更長的繳費期限**必須先修辦法**。

#### 怎麼跑

**用 PowerShell**（Windows 預設，也是本專案其他腳本的慣用殼）。cmd、Git Bash 也都可以，
差別只在換行接續字元。**單行最保險**，複製貼上即可：

```powershell
node scripts/build-shequbang-import.mjs --fee "private/<物業管理費檔>.csv" --result "private/<配位結果>.csv" --announce 2026-12-05 --out "private/社區幫匯入-116機車位.csv"
```

要分行寫，**接續字元三種殼都不一樣**，用錯會噴語法錯誤：

| Shell | 接續字元 |
|---|---|
| PowerShell | 反引號 `` ` `` |
| cmd | `^` |
| Git Bash | `\` |

PowerShell 分行版（行尾是反引號）：

```powershell
node scripts/build-shequbang-import.mjs `
  --fee "private/<物業管理費檔>.csv" `
  --result "private/<配位結果>.csv" `
  --announce 2026-12-05 `
  --out "private/社區幫匯入-116機車位.csv"
```

> 含中文的路徑**一定要加雙引號**，三種殼皆然。
> 加 `--dry` 只驗證不寫檔，適合先看數字對不對。
> 現成測試素材：`private/模擬配位結果.csv`（277 戶／410 台，應收 487,200）。

#### 換一台機器要準備什麼

腳本**只用 Node 內建 API**——Big5 編解碼自建（見 `scripts/lib/big5.mjs`）、CSV 解析來自
`src/data/csv.js`，兩者皆零相依。所以**不必 `npm install`**，裝了 Node 18+ 就能跑。

⚠️ 但兩份輸入檔都在 `private/`、**已 gitignore**，clone 下來不會有——換機器要另外複製過去：

- `第三屆管理費115年05月管理費.csv`（物業提供，查門牌用）
- 配位結果 CSV（12/1 產出；開發測試可用 `模擬配位結果.csv`）

**`--mode merge` — 併入物業月結檔的「機車清潔費」欄**

§4 第 2 項已於 2026-09-17 確認 standalone 可用，故此模式**降為備援**：僅在物業日後改要求
「一戶一月一張帳單」時才需要。
輸出同格式 Big5 CSV，只填「機車清潔費」欄，其餘欄逐格照抄、列數不變（656 列）。

### 門牌 ↔ 戶號對照規則

```text
社區幫  #A1-375 ＋ 樓層欄 2   →   棟 A、單元 1、樓 2
ParkFee 戶號                  →   A2-1                （棟 ＋ 樓 ＋ '-' ＋ 單元）
```

⚠️ **兩邊的中間數字意義相反**：社區幫門牌的是「單元」，ParkFee 戶號的是「樓層」。這是最容易寫錯的地方。

- 街號（`-375`）不參與對照：同一單元不同樓層可能掛不同街號（例 A5 單元多數樓層是 `#A5-367`，唯獨 3 樓是 `#A5-369`）。
- 單元編號**跳過 4**：各棟為 1,2,3,5,6,7,8（店面 S1–S15 反而有 4）。
- 店面走同一條規則：`#S6-40` ＋ 樓層 1 → `S1-6`。
- **1 樓是例外**：社區幫把 1 樓整層歸進 `#S1`–`#S15` 店面門牌，與 eTag 名冊的 `E2-01F`／`H1-01F` 編法不同。住宅棟樓層只有 2–15。
- 樓層欄空白不得當 0 樓：會產出 `A0-1` 這種對不到任何戶的假戶號，腳本已擋（回 `null`）。

規則已用 eTag 名冊 624 筆實際戶別交叉驗證，**吻合 616 筆＝98.7%**；對不上的 8 筆全在 1 樓，屬上述編碼差異而非規則錯誤。

### 多列戶的處理

同一戶可能被物業拆成多列（範本檔 `#F1-321` 2 樓即是）。**只填「管理費 > 0」的主帳列**——
填錯列帳單顯示異常，兩列都填則重複收費。腳本會把所有多列戶列在報告中供物業核對。

### 驗證（腳本自動執行，未通過 exit 1）

- 輸出總額 ＝ 配位結果應繳總額（模擬 277 戶／410 台 ＝ **487,200**，與預估 48 萬相符）
- 所有配位戶都對應得到門牌（對不到的列入「查無門牌」，例如工作人員 `員工-*` 無門牌 → 出帳方式待問物業）
- 未配位戶必為 0；列數與物業檔一致（656 列）
- 輸出為 Big5 無 BOM，且**只有「機車清潔費」一欄與原檔有差異**（已逐格比對確認）
