# 抽籤作業手冊（含機器需求盤點）

> 一年一次的抽籤配位怎麼跑。可在**任何信任的機器**操作（辦公電腦、家裡筆電…），只要符合下方盤點清單。
> 流程：**匯出名冊 CSV → 匯入抽籤頁 → 設種子執行 → 公告結果**。引擎純函式、固定種子可重現、可稽核。

---

## 一、機器需求盤點清單（每台要操作的機器都要備齊）

操作機器分兩種角色，看你要做到哪一步：

### 角色 A：只負責「抽籤」（匯入別人給的 CSV）
最低需求，**不碰任何金鑰**：
- [ ] 一個瀏覽器 + 能開 App（線上 <https://joechiboo.github.io/ParkFee/#/allocate>，或本機 `npm run dev`）
- [ ] 一份名冊 CSV（由角色 B 匯出後給你）

### 角色 B：負責「從 Supabase 匯出名冊」
要直接連 Supabase 撈全名冊，需要 **service_role 權限**：
- [ ] **Node.js**（LTS）安裝好
- [ ] 這個 repo `git clone` + `npm install`
- [ ] **Supabase service_role key**：Dashboard → Settings → API → `service_role`（⚠️ 上帝權限）
- [ ] 在 repo 根的 `.env`（已 gitignored）加一行：
      ```
      SUPABASE_SERVICE_ROLE_KEY=eyJ...
      ```
      （URL 沿用既有 `VITE_SUPABASE_URL`；或另設 `SUPABASE_URL`）

> ⚠️ **service_role 安全**：絕不加 `VITE_` 前綴、絕不進 git、絕不貼到前端。`.env` 已被 `.gitignore` 擋掉。換機器要重設一次。
> 沒裝 Node 的機器（或交給物業）→ 改用「附錄：Supabase 後台匯出」那招，零金鑰。

---

## 二、抽籤流程

1. **匯出名冊**（角色 B，在備齊的機器）：
   ```
   node scripts/export-roster.mjs
   ```
   產出 `private/roster-<時間>.csv`（gitignored 個資夾）。可交給角色 A，或自己接著做。

2. **抽籤**（角色 A 或 B）：開 App → **配位 `/allocate`** →
   - 「匯入名冊 CSV」選那份檔（未匯入則用 20 戶樣本示範）
   - 設**公開亂數種子**（建議當眾公告，如「2027樂菲莊園機車抽籤」）→ **執行抽籤**
   - 需要重抽 → **🎲 重抽（新種子）**；歷次種子/時間都留在「抽籤紀錄」供監察

3. **公告 / 留存**：記下**種子 + 執行時間**（同種子可重現驗算）。配位結果表、落選名單截圖或存檔，交物業辦理簽約繳費（落選者由物業第二階段保底/候補）。

---

## 三、安全與個資

- **service_role**：只在角色 B 機器的 `.env`，永不進 git/前端/`VITE_`。
- **名冊 CSV 是個資**（含全社區車號/電話）：放 `private/`（gitignored），用後妥善刪除/保管，比照紙本名冊。
- 抽籤引擎可重現、可稽核：任何人拿同一份 CSV + 同種子重跑 `distribute`，結果必一致。

---

## 附錄：不用 Node 的匯出法（Supabase 後台 → Download CSV）

給沒裝 Node 的機器或物業：Dashboard → **SQL Editor** 貼上後執行，結果右上 **Download CSV**：

```sql
select v.戶號, v.車號, v.車種, v.第幾輛,
       case when v.身障 then 'Y' else 'N' end 身障,
       case when v.志願小位 then 'Y' else 'N' end 志願小位,
       h.created_at 登記時間, h.電話 聯絡電話,
       array_to_string(h.車位志願, '、') 車位志願,
       case when h.志願落選保底 then 'Y' else 'N' end 志願落選保底,
       '線上' 來源
from vehicle v join household h on h.戶號 = v.戶號
order by v.戶號, v.第幾輛;
```

欄位與 `scripts/export-roster.mjs` 一致，同樣可直接匯入抽籤頁。
