# 抽籤作業手冊（含機器需求盤點）

> 一年一次的抽籤配位怎麼跑。可在**任何信任的機器**操作（辦公電腦、家裡筆電…），只要符合下方盤點清單。
> 流程：**匯出名冊 CSV → 匯入抽籤頁 → 設種子執行 → 公告結果**。引擎純函式、固定種子可重現、可稽核。

---

## 〇、換新機器先設 `.env`（本機跑前端的前提）

`.env` 被 `.gitignore` 擋掉、**不會進 repo**，所以 `git clone` / `git pull` 到的機器上**沒有** `.env`。
沒設好 `.env`，`npm run dev` 一開就報 `缺少 VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY`。

在 repo 根目錄手動建 `.env`，貼上這兩行（**公開值，安全**——anon key 本就打包進線上前端、靠 RLS 把關，見 docs/12 §4.2）：

```
VITE_SUPABASE_URL=https://niwsgtoipwaivbfmdoqp.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_zPiOX90ZgDT23nPFnbUyZw_q5JynE5P
```

- 只做**角色 A（抽籤）**：到這裡就夠，`npm install && npm run dev` 即可開頁。
- 要做**角色 B（匯出名冊）**：再加第三行 `SUPABASE_SERVICE_ROLE_KEY=...`（見下方一、角色 B；⚠️ 這把是 secret，**絕不進 repo**，只能從 Dashboard 手動複製）。

> 為什麼 anon 可以貼進文檔、service_role 不行：anon/publishable 是設計給前端的公開 key（已在 GitHub Pages 的 bundle 裡，人人拿得到）；service_role 繞過 RLS＝上帝權限，外洩＝全社區資料裸奔。

## 一、機器需求盤點清單（每台要操作的機器都要備齊）

操作機器分兩種角色，看你要做到哪一步：

### 角色 A：只負責「抽籤」（匯入別人給的 CSV）
最低需求，**不碰任何金鑰**：
- [ ] 一個瀏覽器 + 能開 App（線上 <https://joechiboo.github.io/ParkFee/#/allocate>，或本機 `npm run dev`）
- [ ] 一份名冊 CSV（由角色 B 匯出後給你）

### 角色 B：負責「從 Supabase 匯出名冊」
要直接連 Supabase 撈全名冊，需要 **service_role 權限**：
- [ ] **Node.js**（LTS）安裝好
- [ ] 這個 repo `git clone` + `npm install`
- [ ] **Supabase service_role key**：Dashboard → Settings → API → `service_role`（⚠️ 上帝權限）
- [ ] 在 repo 根的 `.env`（已 gitignored）加一行：
      ```
      SUPABASE_SERVICE_ROLE_KEY=eyJ...
      ```
      （URL 沿用既有 `VITE_SUPABASE_URL`；或另設 `SUPABASE_URL`）

> ⚠️ **service_role 安全**：絕不加 `VITE_` 前綴、絕不進 git、絕不貼到前端。`.env` 已被 `.gitignore` 擋掉。換機器要重設一次。
> 沒裝 Node 的機器（或交給物業）→ 改用「附錄：Supabase 後台匯出」那招，零金鑰。

## 二、現場 Rundown（跑場腳本｜彩排也照這跑）

> 抽籤日投影大螢幕、操作員照這份唸＋按。**彩排跟正式同一套流程**，差別只在彩排完要把庫清乾淨（見 2.2）。

### 2.0 事前檢查（開場前 30 分，逐項打勾）

- [ ] 筆電 `.env` 有 URL + anon key（見 §〇）；要**發佈/匯出**再加 service_role（§一 角色 B）
- [ ] `npm run dev` 起得來、`/allocate` 開得開（本次 dev 網址以終端機顯示為準，如 `http://localhost:5173/ParkFee/`）
- [ ] 投影接好、**整頁放大**到後排看得清（瀏覽器 Ctrl `+`）
- [ ] **（正式）名冊已匯入**：先 `node scripts/export-roster.mjs` 產 CSV → 登入 **admin** → **🛠 進階**匯入 → 回 `/allocate` 頂端顯示「✓ 已載入匯入名冊（N 戶）」，**戶數對得上**
- [ ] **（正式）物業指派已就位**：`/seat-admin` 的志願小位／無障礙／保留位都鎖好（抽籤會自動扣掉、列「免抽已定」）
- [ ] **（要現場發佈）** admin 已登入、筆電**有網路**（發佈要連 Supabase）
- [ ] **種子先想好**（當眾公告用），如「2027樂菲莊園機車車位抽籤」

### 2.1 現場照跑（投影中）

1. **開場一句**：本抽籤採「填志願＋統一分發」，電腦以**公開種子**抽順序號、**同種子可重跑驗算**，全程留紀錄供監察。
2. **公告種子**：當眾唸出／白板寫下 → 填進「亂數種子」欄。
3. 按 **執行抽籤**。
4. **逐區講解螢幕**：摘要（已配／落選／剩餘）→ 配位結果表（依順序號）→ 展開**各輪抽出序**（Round 0 無障礙／1 一戶一位／2+ 第二輛；✓中 ✗未中）。
5. **宣布落選名單** → 交物業第二階段（保底就近補／候補）。
6. **存證**：填公告日 → **⬇ 下載配位結果 CSV**（順手截圖摘要）。
7. **（正式）📢 發佈結果** → 住戶登入 `/me` 看自己的位。**記下種子＋執行時間**（可重現驗算）。

> 只想換運氣重抽 → 按 **🎲 重抽（新種子）**；歷次種子／時間都留在「抽籤紀錄」。

### 2.2 測好幾次 / 重跑（彩排或當場重來）

分兩種，別搞混：

- **重抽**（同一份名冊、只換運氣）：直接按 🎲 重抽，或改種子再「執行抽籤」。**不用清任何東西**，結果就地更新、歷次留紀錄。
- **重測**（要乾淨重來一輪，尤其**發佈過之後**）：
  1. **🛠 進階 → 清除配位結果**（把上一輪寫回 vehicle 的配位清掉，避免累積／污染）。
  2. 要換名冊 → 重新匯入 CSV；同一份不用重匯。
  3. 回 `/allocate` 重新執行。
- ⚠️ **彩排若用真實庫**：每測完一輪就「清除配位結果」，否則假結果留在正式資料、住戶會查到錯的位。**全部彩排結束，確認庫已清乾淨**再收工。

### 2.3 出錯應變（現場別慌）

| 狀況 | 處置 |
|---|---|
| 種子唸錯／想換 | 按 🎲 重抽 或改種子重跑；舊種子紀錄仍在，透明可查 |
| 頂端顯示「範例 demo」不是真名冊 | 沒匯入成功 → 🛠 進階重匯 CSV，再回 `/allocate` 確認變「✓ 已載入匯入名冊」 |
| 發佈失敗 | 多半沒登入 admin 或沒網路 → **先 ⬇ 下載 CSV 保住結果**，網路好了事後再發佈 |
| 筆電／瀏覽器當掉 | 重開 dev → **輸入同一種子**即可重現同結果（固定種子＝現場保險） |
| 發佈了才發現要重來 | 🛠 進階清除配位結果 → 重跑 → 重新發佈 |

## 三、安全與個資

- **service_role**：只在角色 B 機器的 `.env`，永不進 git/前端/`VITE_`。
- **名冊 CSV 是個資**（含全社區車號/電話）：放 `private/`（gitignored），用後妥善刪除/保管，比照紙本名冊。
- 抽籤引擎可重現、可稽核：任何人拿同一份 CSV + 同種子重跑 `distribute`，結果必一致。

## 附錄：取得名冊的三條路（正常 → 備案）

| # | 做法 | 需要什麼 | 何時用 |
|---|---|---|---|
| **1** | **Dashboard → SQL Editor → Download CSV → `/dev` 匯入** | 能登入 Supabase 後台 | **正案**。理由見下方「為什麼用檔案而非即時載入」 |
| 2 | `/allocate`「⬇ 載入真實名冊」鈕 | 管理員登入即可 | **備案**：後台連不上、或臨時要重跑一次時的快捷路徑 |
| 3 | `node scripts/export-roster.mjs` → `/dev` 匯入 | `SUPABASE_SERVICE_ROLE_KEY` | 第三順位。service_role ＝ 繞過 RLS 的上帝權限，**盡量別帶著它出門** |

> **為什麼正案是「產檔再匯入」而不是一鍵載入**：公開抽籤的核心是**可事後驗算**。
> CSV 是一份**固定快照**——抽籤前可先給委員過目、確認戶數，抽完連同種子一起存證，
> 日後有人質疑時能用「同一份名冊 ＋ 同一個種子」原樣重跑。一鍵載入是即時撈資料庫，
> 跑完就沒有「當時用的是哪份名冊」的證據，登記資料若之後有異動更無從還原。
> 快捷方便，但**證據力較弱**，故列為備案。
>
> 路徑 2 走 `list-roster` Edge Function，**預設不回傳聯絡電話**（抽籤不需要，少送一份個資）；
> 路徑 1、3 產出的 CSV **會含電話**，請視同個資保管、用完刪除。

### 正案的 SQL（Dashboard → SQL Editor 貼上執行，右上 Download CSV）

⚠️ **欄位須與 `registry.js` 的 schema 一致**，少一欄就會出事：漏 `社宅`／`工作人員`
會讓社宅戶與工作人員的分流失效（社宅戶被配到一般位、工作人員跟住戶一起搶位還被收費）；
漏 `車位編號`／`已繳費` 則會讓物業抽籤前已指派的位子被重複配出。

```sql
select v.戶號, v.車號, v.車種, v.第幾輛,
       case when v.身障 then 'Y' else 'N' end 身障,
       case when v.志願小位 then 'Y' else 'N' end 志願小位,
       h.created_at 登記時間, h.電話 聯絡電話,
       array_to_string(h.車位志願, '、') 車位志願,
       case when h.志願落選保底 then 'Y' else 'N' end 志願落選保底,
       case when h.社宅 then 'Y' else 'N' end 社宅,
       case when h.工作人員 then 'Y' else 'N' end 工作人員,
       '線上' 來源,
       coalesce(v.車位編號, '') 車位編號,
       case when v.已繳費 then 'Y' else 'N' end 已繳費
from vehicle v join household h on h.戶號 = v.戶號
order by v.戶號, v.第幾輛;
```

匯入後於 `/allocate` 頂端確認顯示「✓ 已載入…」且**戶數對得上**，再執行抽籤。
**存證**：這份 CSV 連同抽籤種子、執行時間一起留存 —— 三者齊備才重跑得出同樣結果。
