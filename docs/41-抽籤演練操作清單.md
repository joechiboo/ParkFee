## 一、名冊健檢（抽籤前一定要做）

1. 匯出最新名冊：
   ```powershell
   node scripts/export-roster.mjs
   ```
   → 存到 `private/roster/roster-<時間>.csv`，記下印出的**車輛數／戶數**。
2. 健檢（不帶參數會自動抓 `private/roster/` 最新一份）：
   ```powershell
   node scripts/check-roster.mjs
   ```
3. 看最後一行「需處理 N 項」，⚠️ 逐項處理：
   - [ ] **志願小位與車位對不上**：一定要先處理，否則該戶第 1 輛會從結果消失（紅色，名冊頁不能按「已處理」）
     - `D7-11`（11/27 定）：抽籤前住戶仍未回覆 → 持有 239 的車勾回志願小位、輛次換成第 1 輛（照 E1-10 做法），再重匯、重健檢
   - [ ] **沒填志願又沒勾電腦選號**：應為 0；有就打電話催，否則必落選
   - [ ] **工作人員不在員工名單**、**無障礙未核驗**：交物業確認
   - ℹ️ 開頭的是參考，不擋抽籤
4. 網頁同步看：名冊頁勾「只看需聯繫確認」，黃／紅列與上面對得上。
5. 鎖定位核對（唯讀）：
   ```powershell
   node scripts/verify-locks.mjs --phase after
   ```
   - [ ] 沒有「應鎖未鎖」；「多出 N 格」的 N ＝ 名冊裡有車位編號的台數（＝每格都有車掛著，沒有殘留鎖）
   - 規則鎖 71 格＝公益 20、動線轉角 28、498 漏水、641–655 共 15、無障礙保留 108／194、公益自行車 B114–B118
   - 結束時若印 `Assertion failed … async.c` 是 Node 在 Windows 的退出雜訊，結果以前面印的為準
6. 有改資料 → 回第 1 步重新匯出、重新健檢，直到需處理項目都有交代。

> 11/27 中午健檢：340 戶／558 台；需處理 3 項＝志願小位對不上 1（`D7-11`）、工作人員不在名單 4、無障礙未核驗 1（`A3-4`）。
